## Investigar 20 comandos
I. Comando
II. Descripción del comando
III. Ejemplo de caso de uso
--------------------------------------------
1. git init: inicializa un repositorio de Git nuevo o existente en un directorio local, creando una subcarpeta oculta ".git" que contiene toda la estructura de seguimiento.
   Ejemplo: "git init" se ejecuta dentro de la carpeta de tu nuevo proyecto para comenzar a rastrearlo.
2. git clone: Clona o descarga un repositorio remoto existente (por ejemplo, desde GitHub) junto con todo su historial de cambios en tu máquina local.
   Ejemplo: El profesor subió el repositorio base para la práctica final de Ingeniería de Software a GitHub y necesito descargarlo completo a mi computadora para empezar a modificarlo.
3. git status: Muestra el estado actual del repositorio, indicando archivos modificados, preparados o sin seguimiento.
   Ejemplo: Antes de apagar la laptop en la noche, quiero revisar rápidamente qué archivos de mi proyecto modifiqué y cuáles todavía no he agregado al sistema de control de versiones.
4. git add: Añade los archivos modificados o nuevos al área de preparación (staging area), listos para ser guardados.
   Ejemplo: Terminé de escribir las consultas SQL para el módulo de usuarios de mi proyecto escolar y quiero seleccionar ese archivo para que Git sepa que ya está listo para guardarse.
5. git commit: Guarda de forma permanente los cambios preparados en el historial del repositorio local junto con un mensaje descriptivo.
   Ejemplo: Acabo de terminar la lógica del login en mi aplicación web escolar y quiero registrar formalmente este avance en mi historial local con un mensaje claro de lo que hice.
6. git push: Sube los commits locales del repositorio hacia un servidor remoto (como GitHub o GitLab).
   Ejemplo: Ya terminé todo el código de la tarea en mi casa y necesito subir los cambios a mi repositorio en GitHub para que se guarde mi avance en la nube antes de ir a la escuela.
7. git pull: Descarga los cambios más recientes de un repositorio remoto y los fusiona automáticamente con tu rama actual.
   Ejemplo: Mis compañeros de equipo actualizaron el código del proyecto integrador en GitHub mientras yo dormía, y necesito descargar esas novedades a mi laptop antes de seguir programando.
8. git branch: Permite listar, crear o eliminar ramas de trabajo de forma local en el proyecto.
   Ejemplo: Quiero probar una estructura experimental con bases de datos distribuidas para mi tarea sin romper el código principal que ya funciona, así que creo una rama separada para experimentar.
9. git switch: Permite cambiar de una rama a otra dentro del repositorio.
    Ejemplo: Estaba probando código experimental en otra rama de mi práctica, pero me avisaron que hay que corregir un detalle urgente en la rama principal, así que me muevo hacia allá.
10. git merge: Fusiona el historial de una rama específica con la rama en la que te encuentres actualmente.
    Ejemplo: Ya probé y funcionó perfectamente la nueva interfaz que hice en mi rama secundaria, ahora necesito integrarla por completo a la rama principal de la entrega escolar.
11. git log: Muestra el historial detallado de los commits realizados en el repositorio
    Ejemplo: Necesito revisar la lista de mis commits anteriores para recordar en qué parte exacta del código dejé pendiente la práctica de compiladores la semana pasada.
12. git diff: Muestra las diferencias exactas línea por línea entre los archivos modificados y el último guardado.
    Ejemplo: Modifiqué varias líneas en el archivo de configuración de mi servidor virtual y quiero revisar visualmente qué cambios exactos hice antes de guardarlos definitivamente.
13. git stash: Guarda temporalmente los cambios actuales no guardados para dejar el directorio limpio.
    Ejemplo: Estaba a mitad de una función para mi tarea cuando me acordé de corregir un error en otra parte; guardo temporalmente mi avance a medias para cambiar de archivo sin perder nada.
14. git stash pop: Restaura los cambios guardados temporalmente y los limpia de la pila de almacenamiento.
    Ejemplo: Ya solucioné el pendiente rápido y ahora quiero recuperar exactamente el código a medias que había guardado temporalmente para seguir con mi tarea principal.
15. git remote: Permite administrar las conexiones con los repositorios remotos.
    Ejemplo: Creaste un repositorio nuevo en GitHub para mi proyecto de la materia de sistemas operativos y necesito asociar la URL de ese servidor con mi carpeta local
16. git reset: Deshace cambios en el área de preparación o mueve el puntero de la rama a un estado anterior.
    Ejemplo: Agregué por accidente un archivo de credenciales o un log pesado al área de preparación de Git y necesito sacarlo de ahí sin borrar mi archivo local.
17. git rm: Elimina archivos tanto del disco de trabajo como del sistema de seguimiento de Git.
    Ejemplo: Decidí eliminar un diagrama viejo que ya no voy a usar en la documentación de mi proyecto y quiero que Git también lo borre del control de versiones.
18. git fetch: Descarga información y cambios del repositorio remoto sin fusionarlos automáticamente.
    Ejemplo: Quiero revisar si el profesor subió alguna actualización o nueva rama al repositorio de la materia, pero sin alterar todavía mi código local actual.
19. git tag: Crea etiquetas permanentes en puntos específicos del historial para marcar versiones estables.
    Ejemplo: Mi proyecto escolar ya pasó todas las pruebas y voy a entregarlo, así que marco ese commit específico con una etiqueta que diga v1.0-entrega para identificarlo fácil.
20. git blame: Analiza un archivo línea por línea para mostrar quién modificó cada parte y en qué commit.
    Ejemplo: Encontraste una línea de código que está fallando en la práctica grupal y quiero ver exactamente cuál de mis compañeros la escribió para preguntarle el contexto.
